# CSVを増やさず、同じ日の最新版に更新する

同じフォルダに同名CSVがあれば、そのファイルの中身を更新します。ファイルIDと共有リンクを維持し、同じ日に何度実行しても新しい4ファイルを追加しません。別の開催日は日付が違うので、新しい4ファイルを残します。全開催日を合わせて4ファイルに制限する方式ではありません。

既に同名ファイルが複数ある場合は、最も更新日時が新しい1つを更新します。残りは削除・移動しません。応答の `existing_duplicates` に重複数を返します。過去の重複整理は別途行ってください。

## 初回の反映手順

このPRをマージするだけでは、稼働中のGASは変わりません。現在の保存処理はGitHub外のGASにあるため、次の反映が必要です。

1. 現在 `GAS_WEBHOOK_URL` で使っているApps Scriptプロジェクトを開き、現行コードを控えます。既存コードにCSV保存以外の処理がある場合は、一括置換せず、その処理を残して統合してください。
2. CSV受信専用のプロジェクトなら、既存の `doPost` を含むコードを `Code.gs` の内容に置き換えます。同名の `doPost` を2つ残さないでください。
3. 左側の「サービス」の「＋」から **Drive API（v3、識別子Drive）** を追加します。標準Google Cloudプロジェクトを使う場合は、そのCloud側でもGoogle Drive APIを有効にします。
4. 「プロジェクトの設定」→「スクリプト プロパティ」に `KEIBA_FOLDER_ID` を追加し、値に**いま使っている保存先フォルダのID**を設定します。フォルダURLの `/folders/` の後ろの部分です。コードに実際のIDをコミットする必要はありません。
5. エディタ上部から `checkKeibaSetup` を一度実行し、必要な権限を承認します。この確認処理はCSVを作成しません。
6. 「デプロイ」→「デプロイを管理」→現在のウェブアプリの鉛筆→バージョン「新バージョン」→「デプロイ」。実行ユーザー・アクセス範囲は現在の設定を維持します。**既存のデプロイを更新すればURLは同じ**なので、GitHub Secretの変更は不要です。
7. GitHub Actionsを同じ対象日で2回実行し、下記を確認します。
   - 1回目：対象日・各CSV名に対応する最新版が保存される。
   - 2回目：同名ファイルの件数とファイルIDが増えず、中身が更新される。
   - 既存の重複がある場合：重複件数は増えず、選ばれた1ファイルだけ更新される。

## 仕様と制約

- 現行Pythonの `{"files": [{"filename": "...", "content": "..."}]}` に対応し、PythonやGitHub Actions側の変更は不要です。旧単一ファイル形式も受け付けます。
- 同一GASプロジェクトの同時実行をロックし、同名ファイルの二重作成を防ぎます。他のプロジェクトの受信処理にはロックが及ばないため、旧保存処理との二重送信は止めてください。
- 更新にはAdvanced Drive Serviceのメディア更新を使います。大きい組み合わせCSVがあるため、10 MB制限のある `File.setContent` は使いません。Apps Script/API自体の容量・時間上限は残ります。
- 日本語CSVはUTF-8 BOMを1つ付けて保存します。
- 名前・内容・リクエスト内の重複を全件検証してから保存します。同名のGoogleドキュメントなどがあれば更新せず失敗にします。
- 途中でAPIが失敗すると `success: false` と完了済みファイルを返し、現行Pythonは失敗として扱います。再実行しても完了済みファイルは上書きするので増えません。4ファイルの更新はトランザクションではなく、失敗直後は新旧が混在し得ます。成功した実行の4ファイルを使用してください。
- ローカルの振る舞いテストは `node gas/Code.test.cjs`。Google上の実保存とデプロイは未検証です。

公式仕様：[Advanced Drive Service](https://developers.google.com/apps-script/advanced/drive)、[Files.update](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/update)、[File.setContent](https://developers.google.com/apps-script/reference/drive/file#setContent(String))。
