# Driveへの学習履歴の保存

最新CSVの保存処理は維持し、同じ保存先の中に `学習履歴/YYYY-MM/` を
自動作成する。予測・結果をJSONで長期保存し、次回の検証時に読み戻す。
同じ内容の再送は同じファイルを再利用し、既存履歴は削除・上書きしない。
結果の訂正は別バージョンとして保持する。GitHub artifactの90日制限に
関係なく、Driveで保持している予測を学習・検証に使える。

## 1回だけ必要な設定（PRを反映する前）

1. 現在のGASプロジェクトへ、このフォルダの `HistoryArchive.gs` を
   新しいスクリプトファイルとして追加する。既存CSV受信コードは残す。
2. **既存の `doPost(e)` の先頭**（CSVの検証・保存処理より前）に追加：

   ```javascript
   const historyPayload = JSON.parse(e.postData.contents);
   if (String(historyPayload.action || '').indexOf('history_') === 0) {
     return keibaHistoryResponse_(historyPayload);
   }
   ```

   `doPost` をもう1つ作らない。通常のCSV POSTは今の処理にそのまま流れる。
   PR #3のCSV受信コードでも、以前のコードでも同じ追加方法で使える。
3. GASの「プロジェクトの設定 → スクリプト プロパティ」に以下を設定：

   |キー|値|
   |---|---|
   |`KEIBA_FOLDER_ID`|`14qFY5GZl-6m-p3d39CWo_h_Cmw5gskmD`（既にあれば変更不要）|
   |`KEIBA_ARCHIVE_TOKEN`|十分長いランダムな文字列。例は使わず自分用に生成|

4. GitHubリポジトリの「Settings → Secrets and variables → Actions」に
   `GAS_ARCHIVE_TOKEN` を追加。値は上の `KEIBA_ARCHIVE_TOKEN` と同じもの。
   既存の `GAS_WEBHOOK_URL` はそのまま使う。トークンをコードやPRへ書かない。
5. GASで「デプロイを管理 → 編集 → 新バージョン」で現在のWebアプリを更新。
   保存だけでは公開中のWebアプリは更新されない。
6. PR反映後、既存CSV生成ワークフローを実行し、
   「発走前予測をDriveへ長期保存」が成功することを確認する。
   休日や終了後の試運転では発走前予測が0件になり、履歴も増えない。

このGAS追加はスクリプトエディタとデプロイの更新が必要。
PRをマージするだけで既存のGASが自動更新される仕組みではない。

## ファイル数・復元

各回の予測を1ファイル、同じ月に属する新しい結果のまとまりを1ファイルで保存。
馬ごと・買い目ごとのファイルは作らない。中身を含むSHA-256をファイル名にし、
完全に同じデータの再送でファイル数を増やさない。
最新CSVを見に行くときは今までのフォルダ直下を使う。

履歴APIは別トークンで認証し、設定された学習履歴フォルダ内だけを読む。
月単位でページングするので、Googleドライブ全体を検索・取得しない。
保存の応答と読み戻した内容のハッシュを検査し、旧GASの単なるsuccess応答を
長期保存成功と誤認しない。旧GASが受け取ってもCSVを変更しないよう、
履歴リクエストには通常CSV用の `filename` / `files` を付けない。

長期履歴は自動削除しない。手動で履歴を削除すると、その期間の予測は
検証対象から外れる。認証や保存に失敗した場合はワークフローを失敗表示し、
黙って90日だけの保存へ切り替えない。GitHub artifactは予備として残す。
